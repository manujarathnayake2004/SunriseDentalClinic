# CIS6003 Excellent-Band Evidence Matrix

This matrix separates **implemented software evidence** from **evidence that must be produced during the student's genuine execution/reporting**.

## Task A — UML (20)
Implemented evidence: `docs/uml/01_use_case.puml`, `02_class_diagram.puml`, login/appointment/billing/report sequence sources, documented assumptions and design-pattern analysis. Class source includes multiplicities/composition and public/private operations; use case source uses include/extend.

Student evidence still required: render the diagrams, include readable screenshots, explain design decisions/assumptions, evaluate the validity of the design and critically relate the diagrams to implementation.

## Task B — Design patterns and architecture (40)
Implemented evidence: user-friendly Thymeleaf UI, validation, MVC/controller/service/repository three-tier structure, REST billing web service, Strategy billing pattern, XAMPP relational DB, DB view/procedure/function/triggers, sessions/cookies, reports/CSV, reminder alerts, audit log, billing-service health indicator.

Student evidence still required: screenshots of the working interfaces and database objects, architecture explanation, pattern justification/trade-offs and critical evaluation.

## Task C — Testing (20)
Implemented evidence: JUnit/Mockito/Spring Security/MockMvc tests, H2 test profile, GitHub CI, Surefire and JaCoCo artifacts, detailed test plan/traceability.

Student evidence still required: genuine `mvn clean test`/CI success screenshots, test data and actual results, RED/GREEN/REFACTOR examples, evaluation of failures/fixes/lessons learned.

## Task D — GitHub (20)
Implemented evidence: `.github/workflows/java-ci.yml` and `release.yml`, `.gitignore`, release-capable Maven modules.

Student evidence still required: public repository link, genuine version history over development, meaningful branches/merges/pull requests, successful workflow screenshots, tags/releases and latest runnable version evidence.

## Important
No software package can guarantee a mark. The excellent band depends on both a strong implementation and the quality/authenticity of the report, evaluation, screenshots, testing and Git history.
